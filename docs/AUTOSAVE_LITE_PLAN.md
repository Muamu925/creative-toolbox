# Autosave Lite 设计与实现

长时间连续编辑后，如果创作软件在下一次手动保存之前退出，磁盘上的文档可能缺少最近的修改。Lite 在操作停顿时向前台应用请求常规保存。崩溃后还能保留应用留下的恢复资料，供原应用读取。

## 一份文档的保存流程

1. `ApplicationDiscovery.swift` 通过 NSWorkspace 查找运行中的应用，按 Bundle ID 去重。`ApplicationPicker.swift` 提供运行应用选择和手动添加。
2. `SavePolicy.swift` 将保护决定限定在目标应用的本次运行。规则结合最短保存间隔、连续空闲时间、文档与窗口身份，以及上一次已处理的输入活动判断是否有待发请求。
3. `MacSaveBackend.swift` 检查当前进程的权限、活动桌面、前台文档、对话框和键鼠状态。发送前再次检查，目标或输入变化时取消请求。
4. 应用退出后清除本次同意。下次启动重新询问。设置和快照保存在本机，登录启动由用户选择。

## 恢复资料的处理

`RecoveryService.swift` 负责发现恢复目录、复制普通文件、记录相对路径与 SHA-256，并检查源变化和容量限额。`RecoveryWindow.swift` 提供手动选目录、打开系统临时目录、记录另存文件与确认恢复内容的入口。一次完整恢复需要原软件读入数据、另存新文件，再重新打开核对修改。

## 维护重点

优先验证保存权限变化、窗口切换和拖动过程中是否正确推迟请求，再扩展大文件与更多应用版本的实测。验证恢复时，分别记录快照校验、原软件打开结果和重新打开后的内容。版本状态与操作步骤见[验证记录](../autosave-lite/VALIDATION.md)和[使用说明](../autosave-lite/README.md)。
