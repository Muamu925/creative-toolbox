# 创作工具箱：功能地图与集成路线

调研日期：2026-09-11。目标是减少设计、剪辑、三维和音乐工作中频繁切换小工具的成本，优先本地运行、跨应用使用、输出可直接复制或交付的结果。

## 已落地的第一组工具

| 入口 | 现在可以做什么 | 边界 |
| --- | --- | --- |
| 配色工作台 | 项目色板新建、重命名、删除；颜色名称和色号编辑；点击复制 HEX、RGB、HSL | 仅不透明 sRGB 色号，不提供 CMYK / 专色校样 |
| 配色互通 | 整库 JSON 导入追加、导出；当前色板复制 CSS 变量 | JSON 是工具箱自己的 schema 1；尚不支持 ASE / ACO |
| 配色生成 | 以输入颜色生成互补色、邻近色、三等分配色 | HSL 色相规则，作为起点，不能保证审美质量 |
| 图片提色 | 选择本地图片，生成最多六个近似主色的新色板 | 缩略图分桶统计；忽略大部分透明像素；最多 4000 万像素；不保留源图 |
| 文字对比度 | 两个色号实时预览，显示 WCAG AA / AAA 普通与大号文字的结果 | 只检查不透明颜色对比，不代表整体无障碍合规 |
| 创作换算 | 毫米 ↔ 像素、PPI、按目标宽度等比缩放 | 只计算，不修改图片；整数像素四舍五入 |
| 音乐换算 | BPM 转 1/1 至 1/32 音符时长，普通、附点、三连音 | BPM 以四分音符计；不接入 MIDI 或宿主传输状态 |
| 字体对照 | 输入文案，两栏选择本机字体，调整字号和粗体，复制字体名称 | 不安装字体；系统可能回退缺失字形；不判断商用授权 |

新增工具由本项目独立实现，使用现有 Python 标准库和 PySide6，没有复制下列项目的源代码、字体、图标或预设资产，也没有增加第三方运行依赖。

## 产品组织建议

核心体验是一个“项目工作台”：打开项目后，最近的色板、参考图、字体组合、目录和交付预设放在一起。无项目时，各工具仍可独立使用。

推荐形成三个入口：常用工具收藏、按类别浏览、项目工作台。工具超过十个以后，主侧栏保留类别，具体工具放在类别内部；避免不断增加侧栏按钮。迷你面板优先呈现当前色板与参考图，减少覆盖主创作软件的面积。

一种理想的连贯流程：导入参考图 → 提取色板 → 手动调整并命名品牌颜色 → 检查文字对比度 → 对照字体 → 计算目标尺寸 → 导出 CSS / 色卡 → 保存到项目。当前已经能完成中间的配色、对比、字体和尺寸步骤，项目关联与图片色卡导出留待下一组。

## 实现结构

现状：

- `design_core.py`：色号、配色库格式、原子写入与纯数值计算，可独立测试。
- `design_ui.py`：配色、换算和字体页面，通过明确的用户操作访问文件或剪贴板。
- `ui.py`：主窗口提供导航，智能保存控制器保持原结构。
- `palettes.json`：与 `settings.json` 分离，位于同一本地数据目录。配色操作不会修改自动保存模式。

配色库 schema 1：`{schema: 1, palettes: [{name, colors: [{name, hex}]}]}`。最多 100 个色板、每板 100 个颜色；导入最大 2 MB，全部校验成功后才追加。写入失败保留旧内容；检测损坏时保留文件，只读展示示例色板并提示处理。

后续模块增长时，拆成 `tools/colors/`、`tools/reference/`、`tools/type/`、`tools/media/`，通过内置工具注册表提供 id、标题、类别、页面构造器与能力说明。先使用受控内置模块，不设计下载即执行的第三方 Python 插件。

需要持续运行的媒体工作使用工作线程或受控子进程，提供进度、取消、独立输出目录；所有外部命令用参数数组传递。耗时任务不阻塞 Qt 主界面。屏幕取色、截图、全局快捷键放入 Windows/macOS 平台适配层，逐端验证权限、多屏、DPI 与色彩空间。

## 分阶段交付

1. 本次：可独立使用的配色工作台、图片提色、文字对比度、创作换算、字体对照，保留本地数据。36 项测试通过；Windows 原生页面渲染已检查。macOS 尚待真机验收。
2. 下一组：参考图画板、色板排序/收藏、字体收藏、工具搜索；验证“图 → 色 → 字”的连续流程。
3. 批量交付：图片转换压缩、重命名预演、项目模板和交付清单；开始引入可取消的后台任务。
4. 专业适配：媒体分析与转换、工程归档、保存回执和版本历史；按宿主和平台分别验收。

实际使用反馈应关注完成一个小任务需要多少次点击、是否打断创作、结果是否可信、能否带到另一款软件。工具数量本身不作为成功标准。
