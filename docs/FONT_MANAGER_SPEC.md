# 字体工作台：本地字体管理与选字方案

调研与方案日期：2026-09-14。状态：规划，尚未开发。现有 0.2.0 仅有已安装字体的双栏预览、字号 / 粗体设置和名称复制。

## 产品目标

让用户用自己的文案浏览本机字体，把选中的字体按项目和用途整理，比较后带回创作软件。第一版重点完成“找到 → 整理 → 比较 → 下次找回”，随后扩展未安装字体文件和系统激活。

字体工作台属于综合创作工具箱的视觉与文字模块，可服务品牌设计、海报、字幕、视频包装、音乐封面等场景。它与其他模块共享项目入口，保持独立使用能力。

## 参考应用与采用方式

| 官方来源 | 值得借鉴的能力 | 本项目的采用方式 |
| --- | --- | --- |
| [FontBase](https://fontba.se/) | 字体集合、监视文件夹、自定义预览、字体样张 | 分组与素材目录分开；一段用户文案应用到字体列表；文件目录管理后续加入 |
| [RightFont](https://rightfontapp.com/docs) | Font Sets、Tags、Smart Filters，以及支持特定应用的激活工作流 | 将手动分组、标签和条件筛选分开；宿主适配列为单独阶段 |
| [Font Manager](https://github.com/FontManager/font-manager) | 自动属性分类、用户集合、预览比较、字符表 | 从可读取属性开始分类；字符覆盖属于独立检查，不根据预览外观猜测 |

本次仅借鉴工作流，未导入应用代码。Font Manager 是面向 GTK 桌面的 GPL-3.0 项目，不能直接当作我们的 Windows / macOS 后端；若以后复用代码，需单独确认兼容的集成与授权方式。FontBase 与 RightFont 在这里是产品研究来源。

## 分类、分组与标签如何协作

| 组织方式 | 例子 | 行为 |
| --- | --- | --- |
| 系统属性筛选 | 等宽、可用字重、文字系统 | 从字体信息读取，未知属性保持未知；文字系统不代表覆盖该语言全部字符 |
| 手动分组 | 客户 A、海报候选、片头字幕、音乐封面 | 一款字体可加入多个组；移出或删除组只改变整理信息 |
| 风格 / 用途标签 | 正文、标题、复古、圆润、手写、窄体 | 用户批量标记，可同时拥有多个标签 |
| 智能分组 | 已收藏 + 等宽；标题标签 + 可用字体 | 保存一组筛选条件，每次打开重新计算结果，不复制字体 |
| 收藏 | 常用字体 | 一个快捷状态，用于快速筛选，不代替项目分组 |

第一版提供系统属性筛选、手动分组、标签和收藏；可保存的智能分组在文件索引阶段扩展。标签中“宋体 / 黑体 / 楷体 / 手写 / 展示”等先由用户确认；以后读取字体元信息提供分类建议，不把不可靠的 PANOSE 或名称匹配结果直接写成确定分类。

## 第一版：已安装字体的整理和比较

建议将当前“字体对照”升级为“字体工作台”，保留对照能力。

1. **字体库**：枚举 Qt 当前可用的系统字体家族，按家族展示，展开后选择真实可用的样式。允许刷新，不把每个字重都堆成独立卡片。
2. **查找**：按字体名、用户别名、标签搜索；按等宽、文字系统和收藏过滤，显示当前过滤条件与结果数。
3. **自定义预览**：输入标题、字幕或品牌文案，让可见字体卡片同步预览；调整字号，保留中英文与数字快捷样句。
4. **分组与标签**：新建、重命名、删除分组；多选字体加入 / 移出分组、加标签和收藏；普通整理操作不移动字体文件。
5. **对照台**：选 2–4 个家族，使用同一段文案比较；各自选择实际存在的字重 / 样式。不要用合成粗体冒充字体自带的 Bold。
6. **备注**：保存用途、来源链接和用户的授权记录。未填写即未知，不能从字体名称推断是否可商用。
7. **备份**：导入 / 导出分组、标签、备注与偏好；第一版不打包字体文件。缺失字体显示“当前不可用”，保留分组关系。

第一版示例流程：输入“秋日音乐节” → 浏览候选 → 多选加入“音乐节海报” → 标记“标题” → 选择三款对照 → 复制最终字体名 → 下次从该分组继续。

## 界面组织

- 左栏：全部字体、收藏、当前不可用、我的分组；标签作为可组合筛选。
- 顶栏：搜索、自定义预览文案、字号、文字系统 / 等宽过滤。
- 中间：字体家族列表或卡片，显示样张、名称、样式数量、收藏状态；多选后出现批量操作栏。
- 右侧详情：可用样式、分组、标签、备注、来源信息。
- 对照区：从当前选择打开 2–4 栏比较，可返回原来的筛选和滚动位置。

用户面向的名称用“加入分组”“移出分组”“删除分组”；系统字体安装或卸载不混在这些操作里。

## 第二版：管理本地字体文件

引入用户主动选择的目录，首先支持 TTF / OTF / TTC；链接原文件，明确显示目录来源和文件状态。手动刷新先于后台目录监视。

- 未安装字体在工具箱内加载并预览；明确状态为“仅工具箱预览可用”。
- 用 fontTools 读取家族、子家族、PostScript 名称、版本、字重、字符映射和可变轴；缺少字段时保留未知。
- 内容摘要相同的文件显示为同一内容的多个位置；同名字体的不同版本单独保留。
- 文件内容摘要 + TTC face index 标识具体字体；家族是展示分组，不充当文件身份。可变字体实例还需轴坐标区分。
- 读取字符映射检查用户文案中的缺失字符；该结果不保证复杂文字整形或组合序列正确，仍需检查实际预览。
- 来源目录不可用时标为暂不可用，保留标签与分组；重新找到相同内容可以恢复关联。
- 增加可保存的智能分组、重复内容报告、字体样张导出。重复报告不自动删除文件。

## 第三版：系统安装与跨应用激活

需要区分三种状态：工具箱内预览可用、系统 / 用户范围可用、目标创作软件实际识别到字体。

Qt 的 `QFontDatabase.addApplicationFont()` 只保证当前应用能使用该字体，不能据此承诺 Photoshop、Illustrator、Cubase 等软件也可用。

Windows 和 macOS 建立各自的平台接口，分别验证用户范围安装、会话激活、卸载、字体变化通知、同名冲突和应用缓存。Qt 接口不能直接替代这些系统操作；例如 Windows 私有字体加载也只限调用进程。

第一批系统操作只针对明确来源的用户字体；系统保护字体、被占用文件和不可恢复情况给出具体原因。按项目自动激活以及宿主缺字检测在已有可靠适配后再做，不能靠前台窗口名称判断工程所需字体。

## 实现方式与数据演进

继续采用 Python + PySide6。

### 阶段一

- `fonts/catalog.py`：封装 QFontDatabase，提供家族、样式、等宽和文字系统信息。
- `fonts/library.py`：分组、标签、收藏、别名、备注和导入合并；纯数据逻辑可单独测试。
- `fonts/model.py`：Qt 列表模型与过滤模型，共享列表和对照台状态。
- `fonts/page.py`：页面与交互；从现有 `design_ui.py` 中逐步替换 FontPage。
- `fonts.json`：独立的有版本号本地元数据文件，原子保存；与色板库及保存规则分离。

分组采用 UUID，字体关系先绑定本机完整 Qt 家族标识（保留 foundry 限定信息）。该标识用于本机整理，不宣称跨系统或跨语言稳定。备份导入遇到未知 / 歧义家族时显示待匹配，允许用户映射，不静默误合并；刷新后消失的家族保留整理记录。

### 阶段二

增加 fontTools 文件解析和扫描服务，使用增量索引。真实字体文件、多个位置、face、分组和标签构成关系后，采用 Python 标准库 SQLite 保存索引与关系；迁移前备份 JSON，成功后保留回退文件。扫描结果缓存可重建，用户整理信息不能随缓存清理删除。

旧家族标注绑定具体字体前要核对名称、样式和来源，存在多个候选时让用户确认。文件路径和家族显示名称都不单独用作内容身份。

### 性能

列表只绘制可见项，不为数千字体创建数千个 QTextEdit。预览采用模型 / 委托与有容量上限的缓存，输入文案后短暂防抖；选中详情时再加载较重的字符信息。

目录遍历、摘要和元信息解析放在后台，设文件大小、解析超时和错误上限，可取消；有损坏字体时继续其他文件。Qt 字体注册与界面更新由受控的应用线程调度。大量或不可信文件解析阶段评估子进程隔离，不在首屏集中加载全部字体文件。

## 验收要点

- 同一字体加入两个分组，重启后仍在；移出一个组不影响另一个组。
- 删除分组不会卸载、移动或删除字体；多选批量标记结果准确。
- 刷新后字体消失，分组和备注仍在；重新可用后恢复显示。
- 备份导入失败不损坏旧库；重复分组 ID 和歧义字体有明确合并规则。
- 对照台显示真实选中的样式；回退字体不能冒充目标字体完整支持文案。
- 第二阶段覆盖同名不同版本、TTC 多 face、可变字体和损坏文件的样例。
- Windows / macOS 分别检查字体枚举、中文显示、样式选择、滚动和大字体库响应；系统激活另行验收。
