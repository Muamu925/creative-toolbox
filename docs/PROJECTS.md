# 项目规格与资源 · 0.10.0

这是原定 C 阶段「项目组合与交付」的第一步。现有工具仍可独立使用，创建项目不是导入图片、字体对照或复制色号的前置条件。

## 基本流程

1. 从侧栏「项目」或 ⌘4 进入，点击「新建项目」，填写名称。
2. 选择平面 / UI、视频、音乐或三维类型，按需填写客户、截止日期、目录、规格、交付要求和备注。
3. 在「项目资源」关联已导入的图片，添加配色副本和字体候选。
4. 点击「保存项目」。选择配色可预览与复制色号，通过「查看 / 编辑」修改当前项目的配色；选择图片可打开素材页，再置顶参考。
5. 点击「导出说明」生成 Markdown 项目说明。说明记录规格、交付要求、资源标识、配色与字体候选，不包含图片原件或字体文件。

只有项目名称必填。截止日期为 YYYY-MM-DD；其他规格为手动填写的要求，例如「1920 × 1080 px」「25 fps」「120 BPM，四分音符」。这些内容不会自动检测宿主工程或改写换算工具参数。切换类型保留已填字段，切回相应类型可继续编辑；说明导出保留全部已填写规格。

## 引用与副本

| 资源 | 保存方式 | 修改行为 |
| --- | --- | --- |
| 参考图片 | 素材库 ID + 素材 ID + 内容摘要，并保留添加时的名称 | 素材重命名仍能解析；图片已删除、在回收站、原件缺失或活动库不匹配时显示不可用 |
| 项目配色 | 带独立资源 ID 的颜色列表副本 | 仅修改本项目；资源库与其他项目不随之变化 |
| 字体候选 | 带独立资源 ID 的家族名、样式与备注 | 保存选择意图，不包含字体文件、不判断授权；本机缺少字体或样式时保留记录并提示 |

复制项目会生成新的项目 ID 和副本资源 ID，配色与字体备注相互独立；参考图片继续引用同一托管素材。移出项目只移除该条关联或副本，不删除原素材或系统字体。图片移入回收站前，会检查包括已归档项目在内的已保存引用并提示；未保存的项目草稿不计入该检查。

当前未提供原色板 / 字体整理记录的实时共享引用。已有色板与字体库尚未完成稳定 ID 迁移，因此没有将名称、内容指纹或数组下标当作共享引用。下一步按原方案完成迁移后再提供共享模式。

## 保存、归档与检索

修改需点击「保存项目」。工具页之间切换会保留当前页面中的草稿；切换具体项目、复制、归档、导出、完整备份和退出前检查未保存修改，可选择保存、放弃或取消。写入失败保留草稿和原记录。

项目可归档，并从「已归档项目」恢复；首版不提供永久删除。搜索可匹配名称、客户和规格。资源库的统一搜索也能按项目名称、客户、规格、备注和交付要求查找，结果使用项目 ID 跳转。

## 存储和完整备份

新增资料文件 `projects.sqlite3`，`PRAGMA user_version=1`。已有图片 SQLite、色板 JSON 和字体 JSON 格式不变，不迁移或覆写旧库。每个项目及资源拥有 UUID，项目修订号用于拒绝过期编辑覆盖。单次项目保存使用 SQLite 事务；资源库读取与项目副本保存不构成跨库写入。

限制：最多 200 个项目（包括已归档项目）；每项目 100 项资源，每配色 100 色；每条项目记录最多 128 KiB。项目数据库上限 8 MiB，持久化 JSON 总量限制为 6 MiB。损坏或未知格式的项目数据库进入只读保护，不覆盖原文件。

完整 `.ctbackup` 使用 SQLite backup API 获取项目快照，再与原有图片、色板、字体及设置一起校验打包。恢复到新目录后保留项目与图片标识。损坏的项目数据库会阻止创建被误认为完整的备份，不替换已有备份文件。旧版本未识别项目数据库时会拒绝含项目的新备份；请使用 0.10.0 或更高版本恢复。0.10.0 仍可恢复不含项目数据库的旧备份。

## 实现和验证

- `creative_toolbox/projects.py`：规格校验、事务保存、修订冲突检查、资源副本、图片解析、Markdown 导出。
- `creative_toolbox/project_ui.py`：项目列表、表单、资源选择、归档与未保存编辑保护。
- `tests/test_projects.py`：项目隔离、错误写入保护、图片身份与回收站、备份恢复、搜索跳转、退出保护。
- `tools/project_smoke.py`：独立示例资料的规格页和资源页检查，以及说明导出；生成的截图与示例说明位于 `artifacts/projects-review/`。

批量图片输出、实时共享配色 / 字体引用、参考板和宿主工程归档仍属后续步骤。本轮不读取或修改 Photoshop、视频或音乐软件的工程文件。
