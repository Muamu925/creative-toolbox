# 下一阶段产品构思：让工具围绕项目协作

日期：2026-09-11；实现状态更新：2026-09-12。切片 A 已在 0.2.0 实现（排序使用左右箭头），其余未明确标注的内容仍为设计方案。第一轮功能与研究来源见 [功能地图](FEATURE_ROADMAP.md)。

## 1. 产品主张与使用时刻

工具箱逐步成为常驻桌面的“随身创作台”：保存当前项目的参考、色彩、字体和交付要求，让小任务在几次操作内完成。

优先围绕三个时刻设计：

- 开始创作：找到项目、参考图、尺寸、品牌色与字体组合。
- 正在创作：快速取用颜色、查看参考、算尺寸或节拍，少遮挡工作区域。
- 准备交付：检查规格、统一命名、批量生成输出，并形成可分享的说明。

独立使用仍然成立：临时计算尺寸或复制颜色不要求先建项目。

## 2. 四个相互配合的界面

| 界面 | 用来做什么 | 具体内容 |
| --- | --- | --- |
| 主工作台 | 整理与管理 | 最近项目、工具收藏、待完成任务、最近导出 |
| 项目页 | 留住创作上下文 | 参考板、项目色板、字体组合、尺寸/节奏规格、目录入口、交付备注 |
| 悬浮面板 | 创作时快速取用 | 可切换的色条、单张参考图、常用数值；支持置顶与折叠 |
| 搜索面板 | 快速找到动作 | 搜索“取色”“A4”“延迟”“压缩”；先搜索工具，后续支持项目资源 |

主侧栏逐步变成“首页、项目、视觉工具、媒体工具、文件交付、创作保护”，不继续按每个工具增加按钮。

悬浮面板应有明确的拖动区域、关闭与取消置顶按钮；位置越出可用屏幕时自动移回。显示器断开、DPI 变化、macOS 全屏空间切换分别验收。第一版不做鼠标穿透，避免用户找不到恢复入口。

## 3. 色彩工具的下一步

### 色号真正适合粘贴

现有 HEX/RGB/HSL 之外，提供常用格式选项：

- `#355E46`、`355E46`，可切换大小写。
- `rgb(53, 94, 70)`、`53, 94, 70`、各通道单独复制。
- CSS 变量名和变量值分别复制。
- 多个颜色按行或逗号组合复制。

默认格式由用户明确设置；以后可配置“在某应用中使用此格式”。前台应用识别只决定显示或复制格式，不向目标软件自动粘贴、不据此推断当前项目。

### 从颜色收藏到项目色彩

- 每个颜色拥有名称、用途和备注，如“主色”“背景”“文字”“强调”。
- 拖动排序、收藏、最近复制、删除后撤销。
- 锁住主色，再调整其他颜色；对比度不达标时建议候选文字色，由用户采用。
- 色板并排比较，保存 A/B 两版方案。
- 导出带名称与色号的 PNG / SVG 色卡，可直接放进提案。
- 生成简单渐变，调整角度与色标，复制 CSS 或导出图片。

生成规则和算法色彩空间应在工具说明中交代。针对印刷的 CMYK、专色和 ICC 流程单独立项，避免把数学近似值当成印刷结果。

### 屏幕取色

用户主动进入取色模式，显示放大镜和当前色号；点击取色，Esc 取消。完成后可选择“复制”“加入当前色板”。不默认持续录屏，也不自动保存截图。先验收单屏，再扩展多屏、缩放和色彩管理差异。

## 4. 参考图画板：下一版的核心

第一版交互：

1. 拖入或选择本地图片，也可主动粘贴剪贴板中的图片。
2. 在画板上拖动、缩放；支持适应画布、恢复原比例、滚轮缩放。
3. 为图片加标签、备注和来源链接；有“布局”“质感”“字体”“色彩”等可选标签。
4. 选中图片后，点击“提取配色”，显示候选色，确认后保存到项目。
5. 将单张参考图打开为可置顶窗口，随时返回画板。
6. 保存画板并重新打开，恢复图片位置、缩放和备注。

此阶段暂不包含旋转裁剪、多人协作、联网抓图和无限量大图。优先把导入、整理、关联与恢复做完整。

存储选择：第一版导入时复制图片到工具箱管理的素材目录，以便源文件移动后仍可打开；导入前显示合计大小并设容量上限。后续再提供节省空间的“链接原文件”模式，并显示链接失效状态。以内容摘要去重，缩略图独立缓存；打开旧画板时先显示缩略图。

移除画板上的图片只移除引用。只有无项目引用的托管资源才进入可清理列表，清理动作与普通移除分开。

## 5. 项目工作台：轻量起步

新项目只需要名称。目录、客户、截止日期、规格都是可选项。可选择“视觉设计”“视频”“音乐”模板，也可以空白开始。

| 项目类型 | 默认展示的内容 | 示例 |
| --- | --- | --- |
| 视觉设计 | 色板、字体、画板尺寸、出血备注、参考图 | 海报、品牌规范、界面设计 |
| 视频 | 画幅、帧率、参考帧、字体、导出规格、素材目录 | 横版主片与竖版短片 |
| 音乐 | BPM、拍号、调性备注、参考音轨链接、采样率、交付规格 | 编曲工程与分轨交付 |

模板只调整字段和常用工具，不限制项目以后使用其他功能。导出规格先是用户保存的要求，不自动承诺检测宿主工程实际参数。

项目资源规则：

- 全局收藏是可重复使用的素材；项目可引用全局色板，或复制为项目版本。
- 对共享资源修改时明确显示“全局共享”；项目独立副本不会被全局修改影响。
- 切换创作软件不自动切项目，因为同一个软件可能打开多个项目。
- 先使用手动切换与最近项目列表，后续有可靠工程路径时再提出切换建议。
- 项目备份包括工具箱自己的配置与托管资源。打包宿主工程、外链音频或贴图属于另一个功能。

第一张项目规范页可以只包括项目名称、色板、字体名称、目标尺寸和备注，导出为 PNG 或 PDF。这能让整理结果直接用于沟通。

## 6. 字体与排版的自然延伸

- 收藏字体，并保存“标题字体 + 正文字体”的组合。
- 独立调整两栏字号、字重、行距、字距，显示同一段用户文案。
- 提供中英文、数字、标点样例；提醒所选字体缺少哪些字形。
- 把字体组合和样张加入项目规范页。
- 段落助手：清理多余空格、全半角转换、统一标点；先预览变化再复制。
- 字号阶梯：输入基础字号与倍率，生成标题、正文、注释的建议值。

字体名称与排版配置可分享；第一版项目包不复制字体文件。不会从字体名称猜测授权情况。

## 7. 交付助手：先做一条可靠的批处理链

推荐第一条流程：选择图片 → 预览输出尺寸 → 统一命名 → 输出到新目录 → 打开结果。

每个任务显示源文件、目标文件、变更摘要和状态。存在同名输出时先给出冲突说明；取消后保留已完成结果，并清楚标出未完成项。失败项可以单独重试。

后续再扩展：

- 输出多个尺寸，但保留原始长宽比，并明确区分裁剪与留白。
- 压缩前后对比、目标体积试算、透明背景和色彩配置检查。
- 用缩略图与文件名生成联系表，便于选片或审稿。
- 批量重命名先预演；保留原名映射用于撤销，撤销前再次检查文件冲突。
- 项目交付清单允许用户勾选“成品、源文件、字体说明、素材来源”等项；不能仅凭文件存在就宣布交付完整。

可保存的“操作配方”先由内置步骤组合，例如“长边 1600 px → JPEG 质量 85 → 名称前加项目名”。第一版不提供任意脚本执行。

## 8. 视频与音乐：保持各自完整的小流程

视频：先做媒体信息查看、时码与帧数计算、抽帧和联系表。媒体转换采用可取消的后台任务，用户能查看参数。无重编码剪切涉及关键帧边界，不能把任意时间点剪切都标成精确无损。

音乐：先做 Tap Tempo、小节时长、音高与频率换算，再做本地音频元信息。Tap Tempo 显示采样次数，长间隔后重新计时，并允许手动修正。涉及播放的工具默认静音启动，由用户点击播放，不因打开项目而出声。

音乐项目也可使用参考图与配色，例如封面、视觉物料或轨道配色；视频项目也需要字体与交付命名。这些共用资源通过项目连接。

## 9. 下一版的三个交付切片

### 切片 A：颜色随手用（0.2.0 已实现）

范围：色板排序、收藏、删除撤销、更多复制格式、悬浮色条、PNG 色卡导出。

验收：用户在主窗口选中色板，打开悬浮色条，复制不带 # 的色号，在重启后找回同一个色板；导出的 PNG 名称和色号与保存值一致。操作不改变智能保存模式。

### 切片 B：参考图变成可用配色

范围：本地图片画板、拖动缩放、托管图片、备注、保存恢复、提色候选确认、单图置顶。

验收：导入三张图片、改变布局、选一张提色；重启后布局恢复，色板仍在；原始图片移动后已导入的参考图仍可显示。损坏或超限图片给出具体错误，其他图片仍可使用。

### 切片 C：项目一页看清

范围：轻量项目列表、关联画板/色板、字体组合、规格备注、最近项目和规范页导出。

验收：两个项目的独立色板不互相覆盖；能在项目间切换，并导出含色号、字体名称和尺寸的规范页。关闭主窗口后，仍能从托盘打开当前项目。

顺序建议 A → B → C。每个切片都能独立提供价值；完成 C 后再优先做批量交付助手。

## 10. 支持这些体验的实现安排

继续使用 Python + PySide6。避免在 `MainWindow` 中累加全部业务逻辑。

- 工具注册表：稳定工具 ID、名称、分类、搜索词、页面构造器；先是内置注册表。
- 项目服务：项目、资源引用、当前项目、规范字段；不依赖特定宿主软件。
- 资源服务：托管文件、内容摘要、缩略图缓存、容量统计和引用关系。
- 配色服务：从当前页面类中抽出色板操作，主窗口与悬浮色条共享同一份状态。
- 导出服务：明确目标文件和失败结果；从保存的数据渲染色卡/规范页，不直接截取屏幕。
- 任务服务：后台执行图片处理，主线程只处理进度和界面；支持取消与单项失败。
- 平台层：截图、屏幕取色、全局快捷键、置顶行为分别适配 Windows/macOS。

数据演进：项目使用 UUID 引用色板和资源，不以列表下标或文件名关联。当前色板 schema 1 迁移时，为色板和颜色生成稳定 ID，保留迁移前备份；在新数据全部校验并原子写入成功前不替换旧库。导入相同 ID 时提供明确的复制或更新语义，不静默覆盖。

小规模项目和色板继续用有版本号的 JSON。资源数量增多、标签查询与引用事务成为实际需求时，再迁移资源索引到 SQLite；不为尚未实现的功能提前引入整套数据库框架。

## 11. 暂后置的方向

账号、云同步、协作、在线素材市场、AI 生成和第三方插件市场均后置。这些能力应在本地项目与资源模型稳定后按实际需求接入。AI 若引入，优先做“有明确输入和可检查输出”的单项能力，例如标签建议，而不是接管整个工作流。

当前最值得验证的问题是：用户是否愿意把项目色板和参考图长期放在这里；悬浮面板能否减少来回切换；项目规范页是否真的用于交付。可通过本地可见的反馈入口收集意见，第一阶段不需要后台遥测。


## 0.2.0 验证记录

47 项测试通过，覆盖共享面板同步、收藏与重启恢复、复制格式、排序撤销、保存失败、PNG 色值与名称以及自动保存隔离。撤销保留最近 20 次色板修改，仅限本次运行。已有 schema 1 通过可选字段扩展，无项目引用需求时暂不迁移稳定 ID。参考图画板与项目工作台尚未实现。
