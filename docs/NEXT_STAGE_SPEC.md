# 下一阶段方案：让多个创作工具协同工作

更新：2026-09-13。本方案取代上一轮以配色扩展为主的开发顺序。0.2.0 已完成的能力见 [功能地图](FEATURE_ROADMAP.md)；下文全部是设计方案，尚未实现。

## 1. 统一入口与模块边界

主导航建议为：首页、参考与项目、视觉与文字、视频与声音、文件与交付、创作保护。首页包含搜索、收藏和最近使用；工具页面按需加载。类别没有可用功能时在路线页说明，不用大量不可点击的占位按钮填充产品。

搜索范围先限于内置工具名称与关键词，例如“毫米”“时码”“BPM”“字体”。搜索结果显示工具用途和所属类别；同一工具可以被多个场景检索，不复制多套实现。

验收：搜索“毫米”能到达已有换算工具；收藏字体对照后重启仍在；删除收藏不删除工具数据。最近使用只记录工具 ID 与时间，不记录文案、路径或剪贴板内容。

## 2. 参考图画板

任务：用户在创作软件旁持续查看构图、角色、材质、分镜等参考资料。

第一版包含：本地图片导入、拖动与缩放、适应画布、文字备注、单张图片置顶、保存和恢复。提色放在选中图片后的可选动作中。

导入时显示文件数量与合计大小，将图片复制到托管目录，以内容摘要去重，生成缩略图。设单图像素数和总容量上限。源文件移动后，已导入的图片仍可用。移除画板元素只取消引用；磁盘清理由单独操作处理。

验收：导入三张图片，修改布局与备注，重启恢复；移走原图后仍能打开；损坏图片不阻断其他图片；置顶窗口在显示器断开后能回到可用屏幕。第一版不做远程图片抓取或多人协作。

## 3. 视频与音乐计算

| 工具 | 输入与结果 | 需要明确的规则 |
| --- | --- | --- |
| Tap Tempo | 连续点击，显示估计 BPM、点击次数，支持重置与手动修改 | 使用单调时钟；长间隔后重置，单次点击不输出有效速度；不因打开工具而发声 |
| 小节时长 | BPM、拍号、小节数 → 秒 / 分钟 | 显式选择 BPM 的拍值单位；6/8 的八分音符与附点四分音符含义不能混用 |
| 音高与频率 | 音符 / MIDI 音高、自定义 A4 基准 → Hz，或 Hz → 最近音高和音分偏差 | 第一版采用十二平均律，结果注明调律约定；不假装识别正在播放的声音 |
| 帧数与时码 | 帧数、整数帧率 → 时分秒帧，支持反向转换 | 第一版限定整数帧率；29.97 / 59.94 与 drop-frame 另行实现并单独验收 |

验收示例：以四分音符为拍值，120 BPM 的 4/4 四小节为 8 秒；A4 基准 440 Hz 时上移十二半音为 880 Hz；25 fps 的 250 帧为 00:00:10:00。无效值、负数和超出范围输入应解释原因。

## 4. 批量重命名

任务：统一海报文件、渲染帧、镜头素材或音乐分轨的命名。

第一版：用户选择文件 → 添加前后缀 / 替换文字 / 连续序号 → 查看旧名与新名 → 检查冲突 → 执行 → 查看结果。

操作前记录原路径、目标路径及校验信息。处理同目录大小写冲突、Windows 保留名称、名称互换与重命名循环；涉及临时名称时同样避免冲突。撤销前核对目标文件未被替换、旧名未被占用，失败时显示明确清单。

引用这些文件的宿主工程可能因此断链，执行前明确提示；第一版引导用于导出副本和交付目录。工具不推断或改写专有工程内部引用。

验收：10 个文件顺序编号并可撤销；同名结果不会覆盖；预览后文件变化时执行会重新检查；部分失败有准确状态，不宣称整批全部成功。

## 5. 图片导出与任务队列

第一条流程：选择图片 → 选择尺寸 / 格式 / 命名规则 → 查看输出计划 → 输出到新目录 → 打开结果。

首版先支持单一长边尺寸的等比缩放。后续扩展多个规格，裁剪、留白和拉伸必须是明确不同的选项；透明图片转 JPEG 时让用户选择背景色。色彩配置和 EXIF 方向的处理需要有具体策略与样图检查。

任务队列显示每项状态、成功 / 失败数量、输出路径与原因。工作线程或受控子进程处理耗时操作；取消停止后续任务，已完成文件保留并列出。临时输出完成后再原子替换到预先确认的目标，默认不覆盖原文件。

验收：混合尺寸图片得到预期长宽比；损坏图片失败但其他文件继续；取消后界面可响应；重复导出不会无提示覆盖已有文件。

## 6. 项目规格卡

项目创建只要求名称；目录、客户、截止时间和规格可选。用户可以不建项目，直接打开任何工具。

| 场景预设 | 可选字段 |
| --- | --- |
| 平面 / UI | 画布尺寸、PPI、出血备注、色板、字体组合 |
| 视频 | 画幅、帧率、时长要求、音频规格、导出备注 |
| 音乐 | BPM 及拍值、拍号、调性备注、采样率、位深、分轨要求 |
| 三维 | 单位、渲染尺寸、帧率、贴图规格、输出目录 |

工具可以通过“使用当前项目规格”显式填入参数。规格卡记录用户要求，不冒充已经检测到的工程属性；自动检测值须保留文件来源，两者不一致时显示差异。

资源用稳定 ID 引用；共享资源和项目副本明确区分。第一版手动切项目，不能仅凭前台软件自动判断用户在处理哪个工程。项目备份只包含工具箱自己的配置与托管资源，宿主工程归档独立立项。

## 7. 媒体信息与检查

引入 ffprobe 时先提供本地文件信息：时长、视频尺寸、编码、帧率相关字段、音频采样率和通道数。未知值保持未知；可变帧率素材不直接按单一平均值给出精确时码承诺。

下一步允许选择时间点导出单帧，再扩展联系表。媒体命令用参数数组调用，可取消，有超时和输出限制；错误信息转为可读原因。FFmpeg / ffprobe 的具体构建、授权和分发策略在引入时确定。

响度分析后续另立小任务，明确算法标准、目标用途与声道布局。读取或分析媒体不会自动改写文件。

## 8. 实现分层与迁移

1. 为现有页面加入轻量内置工具注册表，不一次重写全部界面。
2. 增加独立参考模块与资源存储；写入带版本号，损坏时保留原文件。
3. 纯计算模块与 UI 分离，视频 / 音乐计算共享单位解析规则。
4. 文件操作计划与执行分离，计划可预览，执行前再次校验。
5. 图片导出与媒体处理共用任务生命周期，具体格式逻辑由模块负责。
6. 项目资源真正需要关联时，再为现有资源增加稳定 ID；迁移前备份，校验成功后原子写入。

小规模设置继续使用有版本的 JSON；当资源索引和事务成为实际需求时再评估 SQLite。Windows / macOS 只在系统能力适配层分支。首阶段采用内置模块，不提供下载即运行的任意 Python 插件。

## 9. 验证与交付顺序

建议依次做工具中心、参考图画板、创作计算扩展，再推进文件整理与项目规格，最后引入媒体引擎。每一组可以独立发布，不靠增加侧栏按钮数量验收。

邀请设计、视频和音乐用户分别完成一个真实任务，记录是否能找到工具、能否理解结果、能否带回原软件继续使用。同步收集 macOS 的安装、权限、全屏与置顶反馈。

云同步、团队协作、AI 生成、在线素材市场和完整剪辑 / 音频编辑暂后置。先让本地工具的输入、结果、保存和交付连贯可靠。
